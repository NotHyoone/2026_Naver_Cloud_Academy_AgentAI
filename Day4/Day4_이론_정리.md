## 1. Part 1 — 왜 서버에서 Claude Code인가

### 1.1 Day 3 회고 — 내 PC에서 "일을 맡기는" AI를 경험했다

- **Claude 기초**: 작업에 맞게 모델 고르기(Opus · Sonnet · Haiku), 세 가지 방식 — Chat(주고받기) · Cowork(맡기기) · Code(만들기)
- **Cowork 위임**: 전용 폴더 `Claude-실습` 하나만 연결, 좋은 위임 = **결과물 + 입력 + 뉘앙스**
- **안전 · 승인 규칙**: 승인 화면 읽기, "작업 전 확인" 모드 유지, 전역 지침 · 프로젝트로 "나만의 규칙" 재사용
- **결과물 공개**: Cowork가 만든 `calendar.html`을 **사람이** 서버에 업로드 → `http://<공인 IP>/calendar.html` 확인

> **오늘의 질문**: 어제는 AI가 내 PC에서 파일을 만들고 사람이 서버에 올렸다. 오늘은 AI가 **서버 안에서 직접** 파일을 만들고 고치게 하려면 무엇이 필요할까? → **Claude Code + CLAUDE.md + 서버 이미지**

### 1.2 서버에서 사용하는 4가지 이유

| 이유 | 설명 |
| --- | --- |
| ① 환경 통일 | OS 차이 제거 — 학생마다 다른 Windows · macOS 대신 모두 같은 Ubuntu에서 같은 명령으로 진행 |
| ② 학생 PC 보호 | 연습장 역할 — 에이전트가 root 권한으로 무엇을 하든 영향은 서버 안에서 끝남 → 내 PC는 안전 |
| ③ 과정 연속성 | Day 1~3 서버 재사용 — 공인 IP · root 비밀번호 · `/var/www/html` 그대로 이어서 사용 |
| ④ 에이전트 경험 | AI가 서버를 직접 다룸 — 명령 실행 · 파일 편집 · 서비스 점검 · 결과 검증을 AI에게 맡기기 |

> **핵심**: 서버는 "망가져도 되돌릴 수 있는 연습장"이다. 단, 되돌리는 방법(**서버 이미지**)을 반드시 함께 준비한다. (Part 7)

### 1.3 Day 1 → Day 2 → Day 3 → Day 4 연결

- **Day 1 · 인프라**: 서버 만들기 — VPC · Ubuntu · Nginx, `index.html` 배포
- **Day 2 · 바이브 코딩**: Claude 활용 — claude.ai로 프롬프트 · 코드 생성 · PRD
- **Day 3 · Claude · Cowork**: 내 PC의 에이전트 — 모델 · 요금제, Cowork로 작업 위임
- **Day 4 · Claude Code**: 서버 위의 에이전트 — AI가 서버를 직접 작업

| 구분 | Day 2 (claude.ai 웹) | Day 3 (Cowork · 내 PC) | Day 4 (Claude Code · 서버) |
| --- | --- | --- | --- |
| 결과가 생기는 곳 | 채팅 화면 · 아티팩트 | 내 PC 폴더의 실제 파일 | 서버의 실제 파일 |
| 실행 | 사람이 복사 → 붙여넣기 → 실행 | AI가 PC 파일 작업(승인 후) · 서버 업로드는 사람 | AI가 서버 명령을 직접 실행(승인 후) |

| 사람의 역할 | 요청 · 복사 | 범위 지정 · 승인 · 업로드 | 요청 · 승인 · 검증 |

## 2. Part 2 — Claude 도구와 AI 에이전트 이해

"대화형 AI"에서 "일하는 AI"로.

### 2.1 Claude를 쓰는 방법 비교

| 방식 | 어디서 | 할 수 있는 일 | 사용 |
| --- | --- | --- | --- |
| claude.ai (웹 · 앱) | 브라우저 · Claude Desktop | 대화, 문서 · 코드 생성, 아티팩트 | Day 2 |
| Claude Cowork | Claude Desktop (내 PC) | 내 폴더의 파일 · 앱 작업을 맡기기(위임) | Day 3 |
| **Claude Code (CLI)** | 터미널 (서버 · PC) | 폴더의 파일 읽기 · 수정, 명령 실행, 여러 단계 작업 | **오늘** |
| Claude Code (VS Code 확장) | VS Code 패널 | CLI와 같은 기능을 편집기 화면에서 | 선택 |

- **Claude Code = 터미널에서 동작하는 AI 코딩 에이전트**
- 오늘은 서버에 **터미널(CLI) 버전**을 설치하고, VS Code Remote SSH 터미널 · MobaXterm(Windows) · ssh(Mac)에서 실행한다.
- 로그인은 교육용 **팀(Team) 계정 좌석**을 사용한다.

### 2.2 AI 에이전트는 어떻게 일하나?

**① 사람 요청** ("서버 상태를 점검해줘") → **② Claude 계획** (필요한 명령과 파일을 판단) → **③ 도구 실행** (승인 후 실행 · 파일 읽기 · 편집) → **④ 결과 확인** (실행 결과를 보고 스스로 검증 · 다음 행동 결정) → **⑤ 보고** (요약 · 다음 제안, 사람이 결과를 검증)

- 챗봇은 답을 **말해주고**, 에이전트는 일을 **직접 하고 결과를 확인**한다.
- ③ 단계마다 Claude Code는 **"이 명령을 실행해도 될까요?"**라고 승인을 요청한다 → **사람이 최종 책임자**.

### 2.3 Claude Code가 하는 일 & 사람이 하는 일

| Claude Code가 하는 일 | 사람이 하는 일 |
| --- | --- |
| 폴더 구조 · 파일 내용 읽기 | 무엇을 할지 명확하게 요청 |
| 파일 생성 · 수정 (변경 내용을 미리 보여줌) | 변경 내용 확인 후 승인 / 거절 |
| 터미널 명령 실행 (`apt`, `systemctl`, `git` ...) | 위험한 명령은 거절 (`rm -rf` 등) |
| 실행 결과를 보고 오류를 스스로 수정 | 브라우저 · 터미널로 결과 검증 |
| 작업 내용 요약 | 안전 규칙(`CLAUDE.md`) 정하기 |

> **IMPORTANT**: AI가 만든 결과는 **반드시 사람이 검증**한다. "됐다고 했으니 됐겠지"가 아니라 `http://<공인 IP>`를 직접 열어 확인하는 습관!

### 2.4 터미널(CLI)이란? — Claude Code가 사는 곳

- **터미널(Terminal)**: 마우스 대신 키보드로 명령어를 입력해 컴퓨터를 움직이는 글자 화면. **CLI(Command-Line Interface, 명령줄 인터페이스)**라고도 부른다.
- **GUI와의 차이**: GUI는 아이콘을 클릭하고, CLI는 명령어를 입력한다.
- 서버에는 보통 **화면(GUI)이 없다** → 서버 관리는 터미널에서 한다. 프로그램 설치 · 파일 만들기 · 서비스 실행 · Git 관리 모두 터미널 작업.
- Claude Code는 이 터미널 안에서 함께 일하는 **AI 동료**다.

```text
GUI (Day 3 · Cowork)     창 · 버튼 · 클릭 / Claude Desktop
        ▼ 서버에는 화면이 없다
CLI (Day 4 · Claude Code) root@yau-web-svr-01:~# 에 명령 입력
        ▼ 같은 터미널에서
claude                    자연어로 요청 → AI가 명령 실행 · 파일 편집
```

### 2.5 claude.ai(브라우저) vs Claude Code(터미널)

| 비교 항목 | claude.ai (브라우저 · Day 2) | Claude Code (터미널 · Day 4) |
| --- | --- | --- |
| 실행 환경 | 웹 브라우저 | 서버 · PC의 터미널 |
| 작업 방식 | 코드를 복사 → 붙여넣기 (사람이 직접) | 파일을 직접 만들고 · 고치고 · 실행 |
| 파일 접근 | 파일을 업로드해야 읽음 | 작업 폴더의 파일을 바로 읽음 |
| 명령 실행 | 불가 (사람이 실행) | 설치 · 점검 · 테스트 명령을 직접 실행 (승인 후) |
| 오류 처리 | 오류 메시지를 복사해 다시 질문 | 터미널 오류를 스스로 읽고 수정 |
| 기억 방법 | 대화창 · 프로젝트 | `CLAUDE.md` (Part 5) |

> **Day 3 Cowork와 비교하면?** Cowork는 내 PC 앱에서 폴더를 맡기는 방식이고, Claude Code는 터미널에서 동작해 **화면 없는 서버에서도** 쓸 수 있다.

## 3. Part 3 — 접속 구조: 터미널 · 파일 주고받기

### 3.1 학생 PC와 서버의 연결 구조

```text
학생 PC (Windows · macOS 무관)                    yau-web-svr-01 (Ubuntu 22.04)
 ├─ VS Code + Remote - SSH 확장 (권장)    ⇄ SSH    ├─ Claude Code (CLI)
 │   편집기 · 터미널 · 탐색기 통합      (TCP 22)   │   서버 안에서 실행 · 서버 파일만 다룸
 ├─ MobaXterm (Windows)                  root@     └─ 작업 폴더
 │   터미널 + 왼쪽 SFTP 파일 창          <공인 IP>     /root/day4-lab/ · /var/www/html/
 └─ 터미널 ssh (macOS · Linux)           + root 비밀번호
     설치 없이 기본 제공 · 파일은 scp
```

- 학생 PC에는 **SSH 접속 도구만** 있으면 된다. **Claude Code는 서버에만 설치**한다.
- 파일은 VS Code 탐색기 / MobaXterm SFTP 창에 끌어다 놓기(Drag & Drop), Mac · Linux 터미널은 `scp` 명령으로 주고받는다.

### 3.2 접속 도구 비교

| 비교 | VS Code + Remote - SSH | MobaXterm | 터미널 ssh |
| --- | --- | --- | --- |
| 지원 OS | Windows · macOS · Linux | Windows | macOS · Linux (기본 내장) |
| 서버 파일 편집 | VS Code 편집기로 바로 편집 | 내장 편집기 / 터미널 | 터미널 (`nano` 등) |
| 터미널 | VS Code 터미널 (`` Ctrl + ` ``) | 기본 탭 | 터미널 앱 그 자체 |
| 접속 방법 | F1 → Connect to Host | Session → SSH | `ssh root@<공인 IP>` |
| 파일 주고받기 | 탐색기 Drag & Drop · 우클릭 Download | SFTP 창 Drag & Drop | `scp` 명령 |
| 추천 | **기본 권장 (모든 학생 공통)** | Windows 사용자 대안 | Mac · Linux 사용자 대안 |

> **TIP**: 세 방법 모두 Day 1의 실습 기록 카드(공인 IP · root 비밀번호)만 있으면 접속할 수 있다.

## 4. Part 4 — 설치 · 첫 실행 · 팀 계정 로그인

브라우저 없는 서버에서 로그인하는 법.

### 4.1 Claude Code 설치 방법

| 방법 | 명령 | 특징 |
| --- | --- | --- |
| **네이티브 설치 (권장)** | `curl -fsSL https://claude.ai/install.sh \| bash` | 한 줄 설치 · Node.js 불필요 |
| npm 설치 (대안) | `npm install -g @anthropic-ai/claude-code` | Node.js 18 이상 필요 |

- 설치 확인: `claude --version` · 설치 진단: `claude doctor`
- 실행: 작업 폴더에서 `claude` 입력

### 4.2 설치가 끝나면 이렇게 보인다

설치 명령은 **직접 타이핑하지 말고 복사 → 붙여넣기**(오타가 나면 설치 실패).

| 화면 문구 | 의미 |
| --- | --- |
| `Setting up Claude Code...` | 설치 진행 중 |
| `✔ Claude Code successfully installed!` | 설치 성공 |
| `Version: 2.1.72` | 설치된 버전 (예시 · 수업 당일 달라질 수 있음) |
| `Location: ~/.local/bin/claude` | 실행 파일 위치 (root면 `/root/.local/bin/claude`) |
| `Next: Run claude --help` | 다음 단계 안내 |

- 바로 `claude`가 안 되면 → `source ~/.bashrc`로 PATH를 다시 읽는다.
- 확인: `claude --version` → 버전을 기록 카드에 적기

### 4.3 서버에서 팀 계정으로 로그인하는 흐름

**① 서버 터미널**: `claude` 실행 → 로그인 방식으로 **Claude 계정(구독)** 선택 → **② 서버 터미널**: 인증 URL 표시 (서버엔 브라우저가 없어 URL을 복사) → **③ 학생 PC 브라우저**: URL 열고 **팀 계정**으로 로그인 → 조직 선택 · 승인 → **④ 서버 터미널**: 브라우저에 표시된 인증 코드를 터미널에 붙여넣기 → **⑤ 확인**: `/status`로 계정 · 조직 · 모델 확인

- **팀(Team) 좌석**: 강사가 보낸 초대 메일을 수업 전에 수락해 둔다.
- **API 키 방식은 사용하지 않는다** (사용량 과금 → 팀 계정과 별도 비용).
- 로그인 정보는 서버의 `/root/.claude/`에 저장 → **서버 이미지에도 함께 저장**된다.

### 4.4 첫 실행 4단계 — 처음 `claude`를 입력하면

| 단계 | 화면 | 할 일 |

| ① 로그인 방식 | Claude account with subscription (Pro · Max · Team) | 구독 계정 선택. **API 키(Console) 방식은 고르지 않는다** (사용량만큼 따로 과금) |

- **④ 폴더 신뢰 = Day 3의 "전용 폴더"**: `/root`나 `/`에서 실행하지 말고 **`/root/day4-lab`에서 실행한 뒤 신뢰**한다. 신뢰한 폴더 안의 파일을 Claude가 읽고 · 고치고 · 실행한다.
- 화면 문구 · 순서는 버전에 따라 조금 다를 수 있다.

## 5. Part 5 — CLAUDE.md 이해하기

AI에게 주는 **"업무 지침서"** — 무엇이고, 어디에 두고, 어떻게 쓰나.

### 5.1 CLAUDE.md란? — 세션이 끝나도 남는 프로젝트 기억

- **문제: AI의 "기억 상실"** — `/exit`로 종료하거나 새 터미널을 열면 이전 대화 내용이 모두 사라진다. 새로 시작할 때마다 "이 서버는 무엇이고, 무엇은 하면 안 되고…"를 매번 다시 설명해야 한다.
- **해결: `CLAUDE.md`**
  - 작업 폴더에 두는 **마크다운(.md) 형식의 텍스트 파일**
  - Claude Code가 **시작할 때마다 자동으로 먼저 읽는** 파일
  - 그래서 "AI에게 주는 업무 지침서", "프로젝트의 기억 노트"라고 부른다.

```text
① cd /root/day4-lab && claude     새 세션 시작
        ▼ 자동
② CLAUDE.md 읽기                  규칙 · 금지 사항 · 작업 방식
        ▼
③ 규칙을 알고 시작                다시 설명하지 않아도 같은 기준으로 작업
```

> **Day 3와 같은 아이디어**: Cowork의 전역 지침 · 프로젝트 지침이 Claude Code에서는 `CLAUDE.md` 파일이다.

### 5.2 무엇에 사용하나? — CLAUDE.md에 적는 4가지

| 항목 | 의미 | 오늘 서버 예 |
| --- | --- | --- |
| ① 프로젝트 설명 | 무엇을 하는 곳인가 | "Day 4 실습 서버, Nginx 웹사이트 `/var/www/html` 운영" |
| ② 자주 쓰는 명령 | 확인 · 실행 방법 | `nginx -t` · `systemctl reload nginx` · 확인 주소 `http://<공인 IP>` |
| ③ 규칙 · 금지 사항 | 지켜야 할 선 | 수정 전 백업 · `index_day1.html` 금지 · `rm -rf` 금지 |
| ④ 작업 방식 | 답변 스타일 | 한국어로 · 명령 전 한 줄 설명 · 끝나면 변경 파일 목록 |

| CLAUDE.md가 있을 때 | CLAUDE.md가 없을 때 |
| --- | --- |
| 세션마다 같은 규칙으로 시작 | 매번 규칙을 다시 설명 |
| 금지 사항을 미리 알고 피함 | 실수한 뒤에야 알려 줌 |
| 팀원 · 다른 서버와 같은 기준 공유 (Git) | 사람마다 다른 결과 |

> **넣지 말 것**: 비밀번호 · `.pem` 키 · API 키 같은 비밀 정보 — `CLAUDE.md`는 Git에 올라가거나 다른 사람이 볼 수 있는 파일이다.

### 5.3 어디에 두나? — 위치에 따라 적용 범위가 다르다

| 구분 | 위치 | 적용 범위 | 주로 적는 내용 |
| --- | --- | --- | --- |
| 사용자 전역 | `~/.claude/CLAUDE.md` | 이 계정의 모든 프로젝트 | 개인 취향 (한국어 답변 등) |
| **프로젝트 (오늘)** | `./CLAUDE.md` (작업 폴더) | 이 폴더 작업 시 | 서버 · 프로젝트 규칙 |
| 하위 폴더 | `./web/CLAUDE.md` 등 | 그 폴더를 다룰 때 추가로 | 그 부분만의 세부 규칙 |

- 여러 개가 있으면 **함께 읽고**, 더 구체적인(안쪽) 규칙이 세부 사항을 보완한다.
- 프로젝트 `CLAUDE.md`는 Git에 함께 커밋 → 다른 사람 · 다른 서버도 같은 규칙 (Lab 06)
- **Day 3 대응표**: 전역 지침 ↔ `~/.claude/CLAUDE.md` · 프로젝트 지침 ↔ `./CLAUDE.md`

### 5.4 만드는 3가지 방법 — 직접 쓰기 · /init · /memory

| 방법 | 설명 |
| --- | --- |
| 방법 1 · 직접 작성 (**오늘 실습**) | 터미널에서 `cat << 'EOF'` 또는 VS Code로 파일 편집 |
| 방법 2 · `/init` | Claude가 폴더를 훑어보고 초안을 자동 생성 |
| 방법 3 · `/memory` | Claude Code 안에서 `CLAUDE.md`를 열어 편집 |

**`/init`이 하는 일** (파일이 여러 개 있는 프로젝트에서 특히 유용)

1. 작업 폴더의 파일 · 폴더 구조를 스스로 탐색
2. 사용 언어 · 프로그램 · 실행 방법을 파악
3. 그 결과를 `CLAUDE.md` 초안으로 작성 → 사람이 읽고 고쳐서 완성

> **자동 생성 = 초안**: `/init`이 만든 내용도 AI가 추측한 결과다. 금지 사항 · 안전 규칙은 **사람이 직접 추가**한다.

### 5.5 CLAUDE.md 기본 구조 — 오늘 서버용 예시

```markdown
# Day 4 실습 서버 (yau-web-svr-01)
## 개요
- Ubuntu 22.04 + Nginx 웹서버
- 웹 파일: /var/www/html (index.html, calendar.html)
## 자주 쓰는 명령
- 설정 검사: nginx -t
- 적용: systemctl reload nginx
- 확인: curl -I http://localhost
## 작업 규칙
- 수정 전 같은 폴더에 백업본을 만든다
- 명령 실행 전 한국어로 한 줄 설명한다
## 금지
- index_day1.html 수정 · 삭제 금지
- rm -rf · SSH · 방화벽 · 계정 변경 금지
```

| 섹션 | 역할 |
| --- | --- |
| 개요 | 이 폴더 · 서버가 무엇인지 |
| 자주 쓰는 명령 | 확인 · 실행 방법을 정확히 |
| 작업 규칙 | 항상 이렇게 일해라 |
| 금지 | 절대 하지 마라 |

**잘 쓰는 요령**

- 짧고 구체적으로 — 한 줄에 한 규칙
- 명령형으로 — "~한다 / ~금지"
- 실수를 발견하면 규칙을 한 줄 추가 → 같은 실수 반복 방지

### 5.6 CLAUDE.md의 한계 — 지침서이지 잠금장치가 아니다

| ✅ 할 수 있는 것 (방향 잡기) | ⚠️ 못 하는 것 (100% 차단) |
| --- | --- |
| 작업 방식 · 금지 사항을 미리 알려 실수를 크게 줄임 | AI가 규칙을 놓치거나 잘못 해석할 수 있음 |
| 세션 · 사람 · 서버가 바뀌어도 같은 기준 | 규칙이 길고 모호할수록 지키기 어려움 |

**그래서 여러 겹의 안전장치**: ① 승인 화면 읽고 판단 → ② `CLAUDE.md` 규칙 → ③ 수정 전 백업 (Part 6) → ④ 서버 이미지 (Part 7)

> **실습 연결**: Lab 04에서 `/root/day4-lab/CLAUDE.md`를 만들고, "index_day1.html을 지워줘"라고 요청해 Claude가 규칙을 근거로 거절하는지 확인한다. `/memory`로 적용 중인 파일도 열어 본다.

## 6. Part 6 — 권한과 안전 규칙

root 권한의 AI 에이전트를 어떻게 통제할까.

### 6.1 root 권한 = 서버의 모든 것을 바꿀 수 있는 권한

- 학생은 서버에 **root로 접속** → Claude Code도 **root 권한으로 동작**
- 가능한 일: 패키지 설치 · 서비스 재시작 · 모든 파일 수정 · 삭제
- 그래서 Day 4 실습은 학생 PC가 아닌 **서버에서** 진행한다.

> **CAUTION**: 실습 서버에는 개인 정보 · 비밀 키 · 중요한 원본을 두지 않는다.

**4단계 안전장치**

| 단계 | 내용 |
| --- | --- |
| 1단계 · 승인 | Claude Code가 실행 전 물어봄 → 사람이 확인 |
| 2단계 · 규칙 | `CLAUDE.md`에 금지 사항 명시 |
| 3단계 · 백업 | 수정 전 파일 백업 (`cp`) |
| 4단계 · 서버 이미지 | 최후의 안전망: 서버 통째로 복구 |

### 6.2 권한 모드 3가지

| 모드 | 동작 | 언제 쓰나 |
| --- | --- | --- |
| **기본 (승인 요청)** | 파일 수정 · 명령 실행 전 매번 승인을 요청 | **Day 4 기본값** — 무엇을 하는지 보며 배우기 |
| 수정 자동 허용 | 파일 편집은 자동 승인, 명령은 여전히 확인 | 익숙해진 뒤 반복 작업 |
| 계획 모드 (Plan) | 실행하지 않고 계획만 세워 보여줌 | 큰 작업 전 방향 확인 |

- `Shift + Tab`으로 모드를 바꾸고, 입력창 아래 표시로 현재 모드를 확인한다.
- 승인 화면에서는 **Yes / 이번 세션 동안 허용 / No(다른 지시)** 중 선택한다.

> **오늘의 규칙**: 승인 요청이 나오면 명령을 **읽고 이해한 뒤** 승인한다. 모르는 명령은 **"이 명령이 무엇을 하는지 설명해줘"**라고 먼저 물어본다.

### 6.3 해도 되는 일 · 승인이 필요한 일 · 금지

| ✅ 자유롭게 (읽기 · 점검) | ⚠️ 확인 후 승인 (변경 작업) | ⛔ 금지 (되돌리기 어려운 작업) |
| --- | --- | --- |
| 파일 · 로그 읽기 | `/var/www/html/index.html` 수정 (백업 후) | `index_day1.html` 수정 · 삭제 |
| 디스크 · 메모리 · 서비스 상태 점검 | 패키지 설치 (`apt-get install`) | `rm -rf` 등 대량 삭제 |
| `/root/day4-lab/` 안의 작업 | Nginx 재시작 · 설정 변경 | SSH · 방화벽 · 사용자 계정 변경 |

이 기준을 `CLAUDE.md`(프로젝트 규칙 파일)에 적어 두면 Claude Code가 작업할 때마다 참고한다.

### 6.4 CLAUDE.md 안전 규칙 예시 — Part 5를 오늘 서버에 적용

```markdown
# Day 4 실습 서버 규칙 (yau-web-svr-01)
## 반드시 지킬 것
- 파일을 수정하기 전에 같은 폴더에 백업본을 만든다. (예: index_before_day4.html)
- 명령을 실행하기 전에 무엇을 하는 명령인지 한국어로 한 줄 설명한다.
- 작업이 끝나면 변경한 파일 목록과 확인 방법을 알려준다.
## 절대 하지 말 것
- /var/www/html/index_day1.html 수정 · 삭제 금지 (Day 1 백업본)
- rm -rf, 대량 삭제, 디스크 포맷 금지
- SSH 설정(/etc/ssh), 방화벽, 사용자 계정 · 비밀번호 변경 금지
```

실습에서는 `/root/day4-lab/CLAUDE.md`로 만들고, Claude Code는 `/root/day4-lab` 폴더에서 실행한다.

## 7. Part 7 — 서버 이미지로 복구하기

연습장이 되려면 **"되돌릴 수 있어야"** 한다.

### 7.1 서버 이미지 vs 스냅샷

| 비교 | 내 서버 이미지 | 스냅샷 |
| --- | --- | --- |
| 단위 | 서버 전체 (OS + 설치 프로그램 + 파일) | 스토리지(디스크) 1개 |
| 복구 방법 | 이미지로 **새 서버 생성** | 추가 스토리지로만 변환 가능 (부팅 불가) |
| 쓰임 | 망가진 서버를 통째로 되살리기 | 디스크에서 데이터 꺼내기 |
| 생성 시점 | 서버 운영중에도 생성 가능 (VPC) | 스토리지 단위 |

> **VMware 스냅샷과 다른 점**: VMware는 같은 VM을 그 시점으로 되돌리지만(Revert), Ncloud 서버 이미지는 **이미지로 새 서버를 만드는 방식**이다. → 새 서버에는 **새 공인 IP**를 연결한다.

### 7.2 망가진 서버 복구 절차

**① 정지** (망가진 서버 `yau-web-svr-01` [서버 정지]) → **② 생성** (최근 서버 이미지 선택 → 이미지로 새 서버 `yau-web-svr-02`) → **③ 연결** (공인 IP 신청 → 새 서버에 연결) → **④ 갱신** (기록 카드에 새 공인 IP 기록 → SSH · 웹 접속 확인) → **⑤ 정리** (옛 공인 IP 반납 · 옛 서버 반납)

- 이미지 안의 파일 · Nginx · Claude Code 설치와 **로그인 상태**가 새 서버에 그대로 들어간다.
- root 비밀번호는 [관리자 비밀번호 확인]으로 다시 확인한다. (인증키 `yau-key-01.pem`)

> **CAUTION**: ⑤를 빠뜨리면 서버 · 공인 IP **요금이 두 배**로 나온다.

### 7.3 매일 수업 종료 30분 전 루틴

**17:30** 작업 저장 · Claude Code 종료 ▶ 서버 이미지 생성 ▶ 이미지 상태 "생성됨" 확인 ▶ 오래된 이미지 정리 ▶ 기록 카드 갱신

| 항목 | 규칙 |
| --- | --- |
| 이미지 이름 | 날짜 · Day 번호를 붙여 구분 (`yau-web-img-day4`) |
| 보관 개수 | 최근 1~2개만 보관, 오래된 이미지는 삭제 (보관 용량만큼 비용 발생) |

## 8. Part 8 — GitHub의 역할 & 실습 미리보기

서버는 **이미지**로, 작업물은 **GitHub**로.

### 8.1 서버 이미지 vs GitHub — 역할이 다르다

| 비교 | 서버 이미지 | GitHub |
| --- | --- | --- |
| 무엇을 남기나 | 서버 전체 상태 | 내가 만든 작업물 (코드 · 문서) |

| 위치 | 네이버클라우드 계정 안 | 인터넷 (서버 밖) |

## 10. 핵심 정리

- **Claude Code = 터미널에서 동작하는 AI 코딩 에이전트**. 화면 없는 서버에서도 파일을 직접 만들고 · 고치고 · 명령을 실행한다.
- **서버에서 쓰는 이유**: 환경 통일 · 학생 PC 보호 · 과정 연속성 · 에이전트 경험. 서버는 "되돌릴 수 있는 연습장".
- **로그인**: 서버에서 `claude` → 구독 계정 선택 → URL을 **내 PC 브라우저**에서 승인 → 코드 붙여넣기 → `/status`. API 키 방식은 쓰지 않는다.
- **CLAUDE.md**: 시작할 때 자동으로 읽는 업무 지침서. 개요 · 자주 쓰는 명령 · 작업 규칙 · 금지 사항을 짧고 명령형으로. 비밀 정보는 넣지 않는다. **지침서이지 잠금장치는 아니다.**
- **안전장치 4겹**: 승인 → `CLAUDE.md` 규칙 → 수정 전 백업 → 서버 이미지.
- **서버 이미지**: Ncloud는 이미지로 **새 서버를 생성**해 복구한다. 복구 후 옛 서버 · 옛 공인 IP 반납 필수. 매일 17:30 이미지 생성 루틴.
- **GitHub**: 서버 이미지는 서버를, GitHub는 내 작업물을 남긴다. 비밀 정보는 절대 올리지 않는다.
