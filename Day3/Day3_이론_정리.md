## 2. Part 2 — Claude란 무엇인가

**Claude는 Anthropic이 만든 AI 어시스턴트**다.

- **설계 원칙 — Constitutional AI**: 유해하거나 차별적인 결과물을 피하고, 불법·비윤리적 활동을 돕지 않으며, 안전하고 유익하게 행동하도록 원칙에 따라 학습 → 인간의 가치에 부합하고 투명하게 작동
- **조정 가능·협업적**: 성격·어조·행동에 대한 지시를 받아들여 더 적은 노력으로 원하는 결과를 얻도록 설계
- **검색창 vs 사고 파트너**: "오늘 환율은?"은 검색창으로 충분하지만, "동아리 예산안을 세 가지 시나리오로 짜고 위험 요소를 알려 줘"는 Claude와 함께 생각할 일이다. 단순 답변 도구가 아니라 **사고 파트너**로 활용한다.

## 3. Part 3 — Claude 모델의 종류·의미·특징

**모델(Model)** = Claude의 답을 만들어 내는 학습된 AI 두뇌. 큰 모델은 더 깊이 생각하지만 느리고 비싸며, 작은 모델은 덜 깊지만 빠르고 저렴하다. 화면 아래 **모델 선택기**에서 언제든 바꿀 수 있고, 모델을 바꾸면 새 채팅이 생성된다.

이름의 의미 — 시(詩)의 길이:

- **Opus(오퍼스)**: 라틴어로 "작품", 음악의 대작 → 가장 큰 모델
- **Sonnet(소네트)**: 14행 정형시 → 균형 잡힌 중간 모델
- **Haiku(하이쿠)**: 일본의 3행 짧은 시 → 가장 작고 빠른 모델

이름 뒤 숫자(버전)는 새 모델이 나올 때마다 올라간다.

| 구분 | Opus | Sonnet | Haiku |
| --- | --- | --- | --- |
| 위치 | 가장 큰 모델 · 최고 성능 | 권장 기본 모델 | 가장 작고 빠른 모델 |
| 강점 | 하이브리드 추론 · 가장 복잡한 작업 | 정교한 기능과 비용 효율의 균형 | 빠른 응답 · 대량 처리 |
| 이럴 때 | 졸업 프로젝트 설계, 복잡한 데이터 분석, 긴 에이전트 작업 | 글쓰기 · 분석 · 코딩 등 일상 업무 대부분 | 간단한 분류 · 요약 · 실시간 응답 |
| 속도·사용량 | 느림 · 사용량 많이 소모 | 보통 | 빠름 · 사용량 적게 소모 |

> 고르는 요령: **Sonnet으로 시작 → 결과가 부족하면 확장 사고를 켜거나 Opus로 전환.** 간단한 일에는 사고 모드를 꺼 두는 것이 가장 빠르다.

### 응답 방식을 바꾸는 설정

| 설정 | 설명 |
| --- | --- |
| 확장 사고(Extended Thinking) | 답하기 전 단계별 추론 → 복잡한 분석에 유용. 지연 시간이 늘어 간단한 질문에는 불필요 |
| 리서치(Research) | 복잡한 질문을 분해하고 수백 개 출처를 탐색해 5~45분 사이에 인용 포함 보고서 작성 |
| 메모리(Memory) | 역할 · 선호도 · 과거 결정 · 작업 스타일을 자동 저장 → 매번 다시 설명할 필요 없음. 설정 > 메모리에서 켜기/끄기·검토·수정·삭제 |

메모리 기본값(강의 자료 기준): Free · Pro · Max는 켜짐, Team · Enterprise는 꺼짐(조직 소유자가 허용하면 켤 수 있음). 수업은 Team 계정이라 메모리가 꺼져 있을 수 있으므로 **Cowork의 전역 지침·프로젝트**로 맥락을 남긴다.

모델의 정확한 이름·버전·출시일·제공 플랜은 자주 바뀌므로 공식 문서(docs.claude.com — Models overview)와 **내 계정의 모델 선택기 목록**으로 확인한다.

## 5. Part 5 — 데스크톱 앱의 세 가지 방식: Chat · Cowork · Code

| 탭 | 작업 형태 | 설명 |
| --- | --- | --- |
| **Chat** | 주고받으며 작업하기 | 묻고 → 답하고 → 방향을 잡고 → 수정. 사고가 주고받음 속에서 일어남 |
| **Cowork** | 작업 맡기기 | 결과물을 설명하면 Claude가 계획·실행·결과 전달, 나는 계획과 결과물을 검토 |
| **Code** | 애플리케이션 구축 | 코드베이스에서 직접 읽기·작성·테스트·명령 실행. 개발자의 작업 공간 |

핵심 기술: 탭을 먼저 고르는 것이 아니라 **눈앞의 작업이 어떤 형태인지 알아차리는 것**. 탭은 자연스럽게 따라온다.

| 지금 하려는 일 | 형태 | 위치 |
| --- | --- | --- |
| 질문, 브레인스토밍, 초안 작성, 한 턴씩 생각 정리 | 주고받으며 작업 | Chat(빠른 진입·받아쓰기·스크린샷) |
| 완성된 결과물로 끝나거나, 여러 도구에 걸치거나, 일정에 따라 실행되는 다단계 작업 | 작업 맡기기 | Cowork(폴더 접근·커넥터·예약 작업·서브에이전트) |
| 코드베이스에서 작성·테스트·실행·배포 | 소프트웨어 구축 | Code 탭(로컬 또는 클라우드) |

- **Chat을 쓸 때**: 답이 다음 질문을 바꿀 때, 내가 계속 그 안에 머물고 싶을 때, 빠르게 끝날 때
- **Cowork를 쓸 때**: 평소 순서대로 해야 할 여러 단계, 결과물이 완성된 파일로 나와야 할 때, 여러 도구·일정에 걸칠 때

### 데스크톱 앱 편의 기능 (Chat)

| 기능 | Mac | Windows |
| --- | --- | --- |
| 빠른 진입 | Option 두 번 → 작업 화면 위로 Claude 호출(Option+Space로 변경 가능) | 지원 안 함 → 작업 표시줄에서 앱 열기 |
| 스크린샷 | Option 두 번 → 영역 드래그 → 메시지에 첨부 | Win+Shift+S로 캡처 → 입력창에 Ctrl+V |
| 창 공유 | Option 두 번 → 앱 창 클릭 → 창 내용 첨부 | 지원 안 함 → Alt+PrtSc로 캡처 → Ctrl+V |
| 받아쓰기 | Caps Lock으로 시작·끝(설정에서 켜기, macOS 14 이상) | Windows 음성 입력 Win+H |
| 데스크톱 커넥터 | 로컬 도구·서비스 연결 | 같음 |

> Chat은 업로드한 것을 읽을 수 있지만 결과는 다운로드로 돌려준다. **폴더에 파일로 저장하는 것은 Cowork**다.

## 6. Part 6 — Claude Cowork란 무엇인가

**채팅이 아니라 위임** — 나머지 업무를 위한 Claude.

Cowork의 핵심 요점 4가지:

1. **업무 자체를 위해**: 답변만이 아니라 업무를 위해 만들어졌다. 로컬 컴퓨터·클라우드 앱·브라우저 등 내가 일하는 곳에서 만난다.
2. **위임**: 결과물을 설명하면 Claude가 전체를 계획·실행·전달한다. 채팅(생각·초안·질문)을 대체하지 않고 더한다.
3. **다단계·장시간**: 여러 도구에 걸치고 시간이 걸리며, 실제 결과물(아티팩트)로 끝나는 작업을 처음부터 끝까지.
4. **통제권은 나에게**: 시작 전 계획을 보여 주고, 전송·삭제·공유 전에는 확인을 요청하며, 언제든 방향을 조정할 수 있다.

Cowork는 데스크톱 앱·웹·휴대폰에서 쓸 수 있지만, **컴퓨터의 파일과 관련된 작업은 데스크톱 앱**이 좋다(파일을 직접 열고 저장). 앱 버전에 따라 전용 탭이 있거나, 일반 대화에서 작업을 설명하면 Cowork 작업으로 전환된다.

### 가장 큰 전환 — "질문"이 아니라 "업무"를 가져오기

| Chat(턴 단위) | Cowork(지속적 수행) |
| --- | --- |
| 도구에서 정보를 가져올 수는 있지만 단계를 연결하는 것은 나 | 여러 도구에서 동시에 정보를 가져오고 여러 단계의 계획을 실행해 완성된 결과물을 반환 |
| 제한된 범위의 교환, 빠른 사고 | Chat에 파일을 업로드하는 것만으로는 메울 수 없는 격차 |

새 사용자의 첫 본능은 "질문 → 답 확인 → 후속 질문"이지만, Cowork는 **평소 직접 하던 업무를 맡길 때** 가장 효과가 크다.

작업 예시: "팀프로젝트 폴더의 회의록(로컬 파일)과 단톡방 공지·과제 공지 메일(여러 도구)을 살펴보고, 모두 종합해서(여러 단계) 교수님께 제출할 한 페이지 진행 보고서를 작성해 줘(실제 결과물)."

### Cowork는 "내 환경 안에서" 일한다

| 어디서 | 수단 | 하는 일 |
| --- | --- | --- |
| 내 파일 | 폴더 | 지정한 폴더 안의 내용을 읽고 결과물을 다시 써 넣음 |
| 내 앱 | 커넥터 | 이메일 · 캘린더 · 메시징 · 드라이브 · CRM의 맥락 |
| 내 브라우저 | Claude in Chrome | 커넥터가 없는 대시보드·포털, 로그인이 필요한 페이지 |
| 내 도구 | 실제 수행 | 할 일을 설명만 하지 않고 실제로 작업 수행 |

### Cowork에 적합한 세 가지 작업 패턴

| 패턴 | 설명 | 예 |
| --- | --- | --- |
| 1. 다단계 | 수집 → 비교 → 초안 → 서식을 하나의 프롬프트로 | 동아리 설문 응답을 주제별 분류 + 인용문 / 실습 보고서·성적 시트에서 수치를 모아 학습 대시보드로 |
| 2. 파일 기반 | 입력도 결과도 실제 파일(Word · Excel · 덱 · PDF) | 보고서 양식 + 회의록 → 팀 프로젝트 제안서 / 지출 내역 시트 → 차트 포함 가계부 보고서 |
| 3. 다중 도구 | Gmail · Slack · M365 · 캘린더 · CRM에 걸친 한 번의 위임 | 캘린더 조모임·참석자·회의록 → 정리 메일 초안 / 동아리 Slack 언급 → 공지문 |

화면에서 보게 될 진행 상황 패널: 원본 파일 읽기 → 비교 및 그룹화 → 결과물 초안 → 서식 지정 → 자체 검토

## 7. Part 7 — Cowork 사용 방법

**설치 → 폴더 지정 → 커넥터 → 권한 → 첫 위임 → 검토**

### 7.1 설치와 작업 공간

1. `claude.com/download`에서 데스크톱 앱(Mac · Windows) 설치 → 로그인(유료 플랜 필요, 오늘은 팀 계정)
2. 프롬프트 바 → **[프로젝트 또는 폴더에서 작업하기]** → 컴퓨터의 폴더 선택. Claude는 폴더 안의 모든 파일(Word · Excel · PDF · PowerPoint 등)을 읽고 결과물을 같은 위치에 저장한다.
3. 원칙: **작업에 필요한 내용을 담은 가장 작은 폴더**

| 폴더 | 판단 |
| --- | --- |
| `~` (Home) · 24,782개 | 너무 넓음 |
| `문서` · 8,910개 | 개인·학교 파일이 섞임 |
| `문서/학교/2026-2학기` · 1,240개 | 아직 넓음 |
| `2026-2학기/Agentic-AI 과제` · 12개 | 필요한 것만 담은 가장 작은 폴더 |

> 폴더 = Cowork가 **읽기 및 쓰기 권한을 모두** 갖는 곳. 메시지에 파일을 첨부하는 것과 달리 열고·편집하고·새로 만들고·정리한다.

### 7.2 커넥터 — 업무가 이루어지는 앱 연결

커넥터 = Claude가 이메일·캘린더·메시징·CRM·클라우드 스토리지에 접근하는 방법. Customize 영역에서 한 번 설정하고, 작업마다 필요한 커넥터만 켜고 끈다.

- 먼저 설정하는 커넥터: 이메일·캘린더(Outlook · Gmail), 메시징(Slack · Teams), 클라우드 스토리지(SharePoint · OneDrive · Google Drive · Box), CRM·프로젝트 도구(Notion · HubSpot · Salesforce · Asana · Linear 등)
- 커넥터마다 할 수 있는 일이 다르다. 읽기·검색만 되는 것도, 생성·편집까지 되는 것도 있으니 켤 때 설명을 확인한다.
- 커넥터가 없는 도구(학교 포털, LMS, 로그인이 필요한 웹 앱)는 **Claude in Chrome**이 다리 역할을 한다.
- 웹·휴대폰에서 시작한 작업은 커넥터에는 접근하지만 **로컬 폴더에는 접근 불가** → 파일이 PC에 있으면 데스크톱 앱에서 시작한다.

### 7.3 권한 모델 — 두 가지 모드와 항상 켜진 안전장치

| 모드 | 동작 | 적합한 경우 |
| --- | --- | --- |
| **작업 전 확인**(기본값) | 이메일 보내기·메시지 게시·파일 공유 등 외부에 영향을 주는 작업 전에 승인을 기다림 | 새로운 도구, 익숙하지 않은 파일, 면밀히 지켜보고 싶은 작업 |
| 확인 없이 작업(주의) | 승인을 위해 멈추지 않음. 더 빠르지만 위험도 큼 | 신뢰할 수 있는 파일·사이트로 작업하며 적극적으로 감독할 때 |
| **삭제 안전장치**(항상) | 두 모드 모두에서 파일을 **영구 삭제하기 전에는 항상 확인 요청**. 예외 없음·건너뛸 수 없음 | — |

추가 제어: 커넥터·MCP(접근 항목·권한 요청 빈도), 웹 접근(관리자가 웹 검색을 끄거나 Claude in Chrome 방문 사이트 제한).

### 7.4 첫 위임 — 좋은 Cowork 프롬프트의 3요소

| 요소 | 의미 |
| --- | --- |
| ① 결과물 | 무엇을 — 형식·분량을 구체적으로("한 페이지짜리 브리프") |
| ② 입력 | 무엇을 보고 — 어떤 폴더·채널, 날짜 범위, 앱 |
| ③ 뉘앙스 | 무엇을 고려해 — Claude가 미처 보지 못할 나의 전문 지식·제약 |

세 요소를 갖추면 **완전한 위임**이 되어 재작업이 줄고, 주고받음이 작업 시작 **전**에 미리 이루어진다.

```text
[결과물] 팀 프로젝트 중간 발표용 2페이지 요약을 작성해줘.
[입력]   팀프로젝트 폴더의 회의록과, 형식 참고용 지난 발표 요약을 사용해.
[뉘앙스] 교수님 피드백을 받는 것이 목적이야. 결정된 내용을 먼저 제시하고,
         확인할 수 없는 내용은 표시해줘.
```

행을 비워 두면 Cowork가 보통 확인 질문으로 물어본다.

### 7.5 작업 중과 작업 후

1. **확인 질문에 답하기**: 사소하지 않은 작업은 대부분 한두 개의 확인 질문으로 시작한다. 방해가 아니라 맥락의 공백을 메우는 과정이다(예: "발표자료.pptx와 발표자료_최종.pptx 중 어느 쪽 형식을 따를까요?").
2. **작업 중 방향 조정**: 잘못된 출처·형식·어조면 바로 개입한다. 끝날 때까지 기다렸다 재생성하려는 본능을 억누른다 — Cowork는 **중단된 지점부터 이어서** 진행한다.
3. **완성된 결과물 검토**: "신뢰하지만 아직 완전히 파악하지 못한 동료의 초안"처럼 읽는다.

| 질문 | 확인 |
| --- | --- |
| 실제 목표를 충족하나? | 요청과 미묘하게 다른 것은 아닌가 |
| 사실이 정확한가? | 어떤 문서를 참고했는지 밝히게 하고 원본과 대조 |
| 지어낸 것 같은가? | 출처를 추적할 수 없는 날짜·이름·인용 = 경고 신호 |

대체로 맞으면 바꿀 점만 알려 주고, 핵심이 틀렸으면 빠진 맥락을 추가한다.

## 8. Part 8 — Cowork 기능

| 기능 | 무엇을 하나 |
| --- | --- |
| 로컬 폴더 접근 | 지정한 폴더의 파일을 읽고 완성된 작업을 같은 위치에 저장 |
| 예약 작업 | 일일 브리핑·주간 요약 등 한 번 설정하면 주기적으로 실행(`/schedule`) |
| 서브에이전트 | 큰 작업을 병렬 백그라운드 워커로 나누고 하나의 결과물로 전달 |
| 프로젝트 | 관련 작업을 자체 파일·지침·메모리를 가진 작업 공간으로 묶음 |
| 브라우저 사용 | Claude in Chrome으로 웹사이트를 탐색하고 찾은 내용을 작업에 가져옴 |
| 컴퓨터 사용 | 커넥터가 없을 때 클릭·입력·앱 열기를 직접 수행(앱마다 권한 요청, Pro · Max 리서치 프리뷰) |
| 플러그인 | 특정 업무용 스킬·커넥터·에이전트 묶음(Customize → Plugins) |

### 예약 작업

- 설정 방법: ① `/schedule` 입력 → 작업과 주기 설명 → Claude가 프롬프트 초안 → 검토·승인, 또는 ② Cowork에서 작업을 한 번 수행 → 결과 확인 → `/schedule`로 반복 작업 전환
- 주기: 매시간 · 매일 · 평일 · 수동
- 아이디어: 금요일 오후 이번 주 수업 정리, 매월 첫날 가계부 요약, 조모임 전 아침 브리핑

| 작업에 필요한 것 | 실행 위치 | 컴퓨터 |
| --- | --- | --- |
| 커넥터만 | 원격 | 꺼져 있어도 됨 |
| 컴퓨터의 파일·앱 | 내 컴퓨터 | 앱이 열려 있어야 함 |

예정 시간에 노트북이 닫혀 있으면 돌아왔을 때 이어서 처리하고 지연을 알려 준다. 예약 작업은 **내가 지켜보지 않는 동안 실행**되므로 처음에는 사본으로 테스트하고, 전송 대신 초안 작성용으로 쓴다.

### 자리를 비운 상태에서 — 휴대폰·웹에서 시작

등굣길 휴대폰에서 "Drive의 이번 주 강의 자료를 한 페이지로 요약해 줘" → 나중에 아무 브라우저에서 진행 상황 확인 → 책상에서 결과물 확인. 하나의 연속된 원격 세션이며 컴퓨터를 켜 둘 필요가 없다.

- 웹·휴대폰 작업은 커넥터에 접근하지만 **컴퓨터의 폴더에는 접근하지 않는다**.
- 작업은 시작된 곳에 머문다. 실행 위치를 바꾸려면 새로 시작한다.
- 조직에서 관리하는 경우 활성화 여부는 관리자가 결정한다.

### Cowork가 나에 대해 학습하는 네 가지 구성 요소

| 요소 | 학습하는 것 | 효과 | 언제 |
| --- | --- | --- | --- |
| 전역 지침 | 내가 누구인지, 어떻게 일하는지 | 모든 작업이 내 역할·형식·선호도에 맞춰 시작 | 모든 대화에 적용할 규칙 |
| 프로젝트 | 하나의 작업 흐름에 대한 맥락 | 이미 팀에 속한 사람처럼 파일·이력·결정 사항에 접근 | 반복되는 작업 흐름 |
| 스킬 | 특정 프로세스를 어떻게 수행하는지 | 우리 템플릿·기준·단계대로 | 같은 워크플로를 여러 번 설명하고 있을 때 |
| 플러그인 | 역할·분야의 전문성 | 제너럴리스트 → 스페셜리스트 | 팀과 공유할 것이 생겼을 때 |

독립적이면서 서로 누적되며, 첫날부터 네 가지를 모두 시작할 필요는 없다.

### 전역 지침과 프로젝트 — 두 계층의 상시 컨텍스트

- **전역 지침 — "나"에 대한 브리프**: 설정 → 전역 지침(버전에 따라 "Claude를 위한 지침"). 한 번 작성하면 모든 세션(모든 채팅·예약 작업)에서 참조. 내가 누구이고 무슨 일을 하는지, 자주 쓰는 약어, 결과물 형식·길이·어조를 담는다. 계속 반복하는 수정 사항("결론 먼저")이 전역 지침 후보다.
- **프로젝트 — "작업 대상"을 위한 공간**: 이 프로젝트에만 적용되는 지침, 프로젝트에 속한 예약 작업, 참고할 폴더·링크, 프로젝트 안 대화에서 Claude가 스스로 쌓는 메모리. 시작 방법은 처음부터 · 컴퓨터의 기존 폴더에서 · 기존 프로젝트에서. 팀 프로젝트, 과목별 반복 결과물(주간 실습 보고서), 동아리 행사·공모전 준비에 적합.

프로젝트 밖에서는 전역 지침을 제외하면 매 세션이 새로 시작되고, 프로젝트 안에서는 모든 대화가 Claude가 아는 내용에 더해진다.

### 스킬 — 재사용 가능한 플레이북

스킬 = 특정 종류의 작업을 원하는 방식으로 수행하도록 Claude에게 가르치는 **파일·리소스 폴더**. 작업이 설치된 스킬과 일치하면 자동으로 불러오며, "주간 실습 보고서 작성 스킬을 사용해 줘"처럼 명시할 수도 있다.

| 구성 | 역할 |
| --- | --- |
| 지침(`SKILL.md`) | 무엇을·언제·어떻게 — 신입 동료용 운영 매뉴얼 |
| 자산 | 로고, 브랜드 템플릿, 슬라이드 마스터, 폰트 |
| 참고 자료 | 좋은 결과물 예시, 스타일 가이드, 과거 작업물 |
| 스크립트 | 매번 동일해야 하는 계산·비교·포맷 코드 |

필요한 것만 포함하며 `SKILL.md` 하나로 충분한 스킬도 있다. Claude와 함께 만들 수 있다: "[반복적인 프로세스]를 위한 스킬을 만들고 싶어요. 알아야 할 내용을 안내해 주세요." 설치 후 Customize에서 확인하고 수정 사항을 말하면 바로 업데이트된다.

## 9. Part 9 — 안전 수칙과 주의사항

### 안전하게 작업하기 위한 모범 사례

1. **실수가 중요한 것에 닿지 않도록 설정**
   - 전용 작업 폴더 사용. Documents · Downloads · Desktop 연결은 새 동료가 내 모든 파일을 뒤지게 하는 것과 같다.
   - 대체 불가능한 것은 Cowork가 접근할 수 없는 곳에 먼저 백업한다.
   - 새로운 워크플로는 사본으로 먼저 테스트한다.
2. **잘못된 작업의 여지를 남기지 않는 프롬프트**
   - 파괴적인 동사는 구체적으로: "초안에서 해당 섹션을 제거하되, 파일은 유지해 줘"
   - 범위를 명시: "가장 최근 3개 파일만", "아무에게도 보내지 마 — 초안만"
   - 예약 작업은 처음에 초안 작성용으로
3. **그 순간의 세 가지 점검**
   - 계획을 한 번 읽기 — 타당한가? 순서·출처가 맞나?
   - 예상치 못한 패턴 주시 — 언급하지 않은 파일·사이트를 건드리면 중단. "뭔가 이상하다"는 느낌은 실제 신호다.
   - 확인 프롬프트를 신중하게 승인 — **대부분의 실수는 안전장치 실패가 아니라 의도와 다른 확인을 그냥 클릭해서** 일어난다.

Cowork가 적합하지 않은 경우:

- 감사 추적이 필요한 규제 대상 워크플로(Cowork 활동은 감사 로그에 기록되지 않음, Enterprise Compliance API는 베타)
- 감독 없이 맡기기 어려운 일 — 과제·서류 제출, 공개 게시물·공지 게시, 다른 사람에게 보내는 메시지
- IT가 승인한 경계 밖의 매우 민감한 개인 데이터

### Q&A — NCP Linux 서버에 Cowork를 설치할 수 있나?

**설치할 수 없다.** Cowork는 Claude 데스크톱 앱(Mac · Windows) 안의 기능이고, Day 1의 Ubuntu 서버는 화면(GUI)이 없는 Linux 서버라 데스크톱 앱을 설치·실행할 수 없다. 웹·휴대폰의 Cowork는 클라우드에서 실행되며 커넥터에 접근할 뿐, 내 서버에 SSH로 들어가 작업하지 않는다. 서버에서 AI 에이전트가 필요하면 **Claude Code(CLI)** — Day 4.

| 구분 | Cowork | Claude Code |
| --- | --- | --- |
| 실행 위치 | 내 PC 데스크톱 앱(Mac · Win) | 터미널(서버 · PC) |
| 다루는 것 | 내 PC 폴더 · 앱 · 커넥터 | 서버 파일 · 명령 · Git |
| 서버와의 관계 | 파일을 만들고 사람이 업로드 | 서버 안에서 직접 작업 |
| 과정 | Day 3 | Day 4 |

> 서버 접속 정보(root 비밀번호 · `.pem`)는 Cowork 채팅·지침·실습 폴더에 넣지 않는다.

### 우리 수업의 Cowork 안전 수칙 6가지 (Lab 00~07 전체 적용)

1. **전용 실습 폴더** — `문서/Claude-실습` 하나만 연결(문서·다운로드·바탕화면 연결 금지)
2. **복사본만 사용** — 원본은 다른 곳에 보관, 입력 폴더에는 사본
3. **민감 파일 금지** — 주민번호·계좌·비밀번호·서버 접속 정보 금지
4. **승인 화면 읽기** — "작업 전 확인" 유지, 내용을 읽고 나서 승인
5. **결과는 새 파일로** — 원본 수정 금지, 결과 폴더에 저장
6. **공용 PC 연결 해제** — 폴더 연결 해제, 지침 정리, 로그아웃
