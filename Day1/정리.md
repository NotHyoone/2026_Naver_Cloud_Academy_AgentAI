# Day 1 정리: 네이버클라우드 기초와 웹 서버 구축

> 참고 자료: `네이버클라우드_강의자료/Day-1_이론_네이버클라우드-기초_v5_marp.pdf`, `네이버클라우드_강의자료/Day-1_실습_네이버클라우드-기초_v5_marp.pdf`
>
> 강의안에 적힌 콘솔 메뉴, 상품 사양, 리전 지원 범위는 자료 작성 시점의 내용일 수 있다. 실습 당일 콘솔과 공식 안내에서 현재 설정을 확인한다.

## 1. 학습 목표

- 클라우드 컴퓨팅과 NAVER Cloud Platform(NCP)의 기본 구조를 설명한다.
- VPC와 Public/Private Subnet, ACG, 공인 IP의 역할을 이해한다.
- Ubuntu 서버에 SSH로 접속하고 Nginx 웹 페이지를 배포한다.
- Day 2에 이어 쓸 서버 접속 정보와 `index_day1.html` 백업을 안전하게 보관한다.

## 2. 핵심 개념

### 클라우드 컴퓨팅

서버, 네트워크, 스토리지 같은 IT 자원을 필요할 때 만들고 사용량에 따라 비용을 내는 방식이다. 직접 데이터센터를 구축하는 초기 투자(CAPEX)를 사용량 기반 운영비(OPEX)로 바꾸고, 자원 확보와 확장을 빠르게 할 수 있다.

서비스 모델은 관리 책임의 범위로 구분한다.

| 모델 | 제공 범위의 예 | 사용자가 주로 관리하는 것 |
| --- | --- | --- |
| IaaS | 가상 서버, 네트워크, 디스크 | OS와 애플리케이션 |
| PaaS | 애플리케이션 실행 플랫폼 | 애플리케이션과 데이터 |
| CaaS | 컨테이너 실행·관리 환경 | 컨테이너 이미지와 워크로드 |
| FaaS | 함수 단위 실행 환경 | 함수 코드와 실행 설정 |

### NCP 콘솔과 계정

- 포털 계정으로 콘솔에 들어가 서비스와 리소스를 관리한다. 강의 실습은 **Korea 리전, VPC 플랫폼** 기준이다.
- VPC 플랫폼과 Classic 플랫폼은 네트워크 및 리소스 구성이 다르므로 실습 전 플랫폼을 확인한다.
- Sub Account는 주 계정 정보를 공유하지 않고 사용자별 권한을 나누는 IAM 수단이다. 필요한 정책만 부여하고 MFA를 사용한다.
- API를 이용한 자동화에는 인증 키를 안전하게 관리해야 한다. 키나 비밀번호를 코드, 공개 저장소, 공유 문서에 넣지 않는다.

### 네트워크

- **VPC**: 계정의 클라우드 리소스를 격리하는 사설 네트워크 공간.
- **Subnet**: VPC 주소 범위를 용도별로 나눈 네트워크. 서버는 Subnet 안에 배치한다.
- **Public Subnet**: 인터넷 경로를 구성할 수 있어 웹 서버처럼 외부 연결이 필요한 리소스에 사용한다.
- **Private Subnet**: 외부에서 직접 접근하지 않는 내부 서비스나 데이터베이스에 사용한다.
- **ACG(Access Control Group)**: 서버 NIC에 적용하는 방화벽 규칙. 프로토콜, 출발지 CIDR, 포트 기준으로 접근을 제어한다.
- **공인 IP**: 인터넷에서 서버로 연결할 때 쓰는 주소다. 서버와 연결·해제하는 자원이며 사용 중 비용이 발생할 수 있다.
- **CIDR**는 네트워크 주소와 prefix 길이로 주소 범위를 표현한다. 예를 들어 `10.0.0.0/16`은 VPC 범위, `10.0.1.0/24`는 그 안의 서브넷 범위다.

실습 예시 주소 설계:

| 리소스 | 이름 | 주소 범위 | 용도 |
| --- | --- | --- | --- |
| VPC | `yau-vpc-01` | `10.0.0.0/16` | 실습 사설망 |
| Public Subnet | `yau-pub-sub-01` | `10.0.1.0/24` | 웹 서버 |
| Private Subnet | `yau-pri-sub-01` | `10.0.2.0/24` | 내부 서비스·DB 예시 |

### 서버와 스토리지

- 가상 서버는 선택한 이미지(OS), vCPU, 메모리, 디스크, 네트워크로 구성한다. 워크로드에 맞춰 Standard, High CPU, High Memory 등의 유형을 고른다.
- Block Storage는 서버에 디스크처럼 연결해 OS, 애플리케이션, 작업 데이터를 저장한다.
- Object Storage는 버킷에 객체(파일과 메타데이터)를 저장한다. 이미지, 문서, 백업, 정적 웹 파일 등에 적합하다.
- 서버를 정지해도 디스크 등 리소스 비용이 남을 수 있다. 강의에서 이어 쓰도록 지정한 서버와 공인 IP는 Day 2 전까지 유지하고, 전체 실습이 끝난 뒤 안내에 따라 반납한다.

## 3. 실습 흐름

### 시작 전 확인

- NCP 계정 로그인과 콘솔 진입 확인
- 리전 `Korea`, 플랫폼 `VPC` 확인
- SSH 클라이언트 준비(Windows PowerShell/VS Code Remote SSH 또는 macOS/Linux 터미널)
- 리소스 이름에 본인 식별자를 붙여 다른 학습자 리소스와 구분
- 인증키 파일을 내려받을 위치와 안전한 보관 방법 준비

### 필수 실습 A: VPC 및 Subnet

1. VPC `yau-vpc-01`을 `10.0.0.0/16`으로 생성한다.
2. Public Subnet `yau-pub-sub-01`을 `10.0.1.0/24`로 생성하고 인터넷 통신을 사용하도록 설정한다.
3. Private Subnet `yau-pri-sub-01`을 `10.0.2.0/24`로 생성하고 인터넷 직접 통신을 사용하지 않도록 설정한다.
4. 두 Subnet이 의도한 VPC와 Zone에 연결됐는지 확인한다. 강의안은 KR-1을 예로 든다.
5. 라우팅과 네트워크 ACL을 확인한다. Public Subnet에 인터넷 경로가 필요한지와 기본 규칙을 콘솔에서 확인한다.

### 필수 실습 B: Ubuntu 서버와 웹 페이지

1. Ubuntu Server 22.04 LTS 이미지를 선택한다.
2. `yau-vpc-01`의 **Public Subnet**에 서버를 생성한다. 예시 사양은 Generation 2, 시간 요금제, Standard 2 vCPU/4GB다.
3. 인증키를 생성하고 `.pem` 파일을 다운로드한다. 이 파일은 재다운로드할 수 없는 것으로 강의안에 안내되어 있으므로 안전하게 보관한다.
4. ACG 인바운드 규칙을 만든다.

   | 프로토콜 | 포트 | 목적 |
   | --- | --- | --- |
   | TCP | 22 | SSH 관리 접속 |
   | TCP | 80 | HTTP 웹 접속 |

   강의안 예시는 출발지를 `0.0.0.0/0`으로 열지만, SSH(22)는 가능한 경우 본인 공인 IP로 제한한다. 실습 종료 후 불필요한 외부 공개 규칙을 정리한다.

5. 서버가 운영 중이 되면 공인 IP를 신청해 서버에 연결한다.
6. 콘솔에서 인증키를 사용해 root 비밀번호를 확인하고, IP·비밀번호는 개인 기기에만 기록한다. 채팅, 공개 문서, 저장소에 입력하지 않는다.
7. 접속한다.

   ```bash
   # 키 파일 방식 (macOS/Linux)
   chmod 400 yau-key-01.pem
   ssh -i yau-key-01.pem root@<공인_IP>

   # 비밀번호 방식 (강의안 공통 예시)
   ssh root@<공인_IP>
   ```

8. Ubuntu 서버에서 Nginx를 설치하고 실행한다.

   ```bash
   apt-get update -y
   apt-get install -y nginx
   systemctl start nginx
   systemctl enable nginx
   systemctl status nginx
   ```

9. 브라우저에서 `http://<공인_IP>`에 접속해 기본 Nginx 페이지를 확인한다. HTTPS가 아니라 HTTP 주소를 사용한다.
10. `/var/www/html/index.html`에 강의 예제 또는 직접 만든 정적 HTML을 배포하고 브라우저에서 확인한다. 한글 표시를 위해 `<meta charset="UTF-8">`을 포함한다.
11. Day 2에서 되돌릴 수 있도록 백업을 만들고 확인한다.

   ```bash
   cp /var/www/html/index.html /var/www/html/index_day1.html
   ls -l /var/www/html/
   ```

### 선택 실습

- **Sub Account/MFA**: 최소 권한 정책을 부여하고 OTP 기반 MFA를 설정한다.
- **콘솔 개인화**: 대시보드 위젯과 VPC, Server 등 자주 쓰는 서비스 북마크를 설정한다.
- **Object Storage 정적 웹**: 버킷을 만들고 파일을 업로드해 정적 웹 호스팅을 확인한다. 공개 읽기가 필요한 경우에도 공개 쓰기 권한은 부여하지 않는다. 실습 뒤 버킷 안 파일을 먼저 지우고 버킷을 삭제한다.
- **개인 페이지 생성**: 외부 리소스 없이 HTML 한 파일로 페이지를 만들 수 있다. 프롬프트에 공인 IP, 비밀번호, 연락처 등 민감정보를 넣지 않는다.

## 4. 문제 해결 메모

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 콘솔에 VPC 메뉴가 없음 | 플랫폼이 VPC인지 확인 |
| Subnet에서 VPC가 보이지 않음 | VPC 생성 상태가 운영 중인지 확인한 뒤 새로고침 |
| SSH 연결 시간 초과 | 서버가 Public Subnet인지, 공인 IP가 연결됐는지, ACG TCP 22가 허용됐는지 확인 |
| SSH 권한 거부 | root 비밀번호를 다시 확인하고 키 파일 방식이면 올바른 키인지 확인 |
| 웹 페이지 접속 실패 | ACG TCP 80, Nginx `active (running)`, `http://` 주소 확인 |
| 기본 Nginx 페이지만 보임 | `index.html` 내용을 확인하고 브라우저를 강력 새로고침 |
| HTML 한글 깨짐 | `<meta charset="UTF-8">` 확인 |
| SSH 키 권한 경고 | macOS/Linux에서 `chmod 400 <키파일>` 적용 |

## 6. 핵심 요약

Day 1의 핵심 흐름은 **VPC/Subnet 설계 → ACG로 필요한 포트 허용 → Public Subnet의 Ubuntu 서버 생성 → 공인 IP와 SSH 연결 → Nginx 설치 → 웹 페이지 배포 및 백업**이다. 네트워크 공개 범위와 인증정보 보관을 신중히 하고, Day 2에 필요한 서버·공인 IP는 지정된 시점까지 유지한다.
